# 保留中のAI挙動ケース（d2探索の限界に起因・将来の学習/深化で解消したいもの）

このファイルは「対戦シミュレータのAIが取った違和感のある手で、**現状は深さ2（d2）探索の限界として一旦保留している**ケース」の記録。
今後 **探索深化（d3）／相手モデル改善／価値ネット再学習** を行う際の **合否判定基準** として使う。
（常時読み込むCLAUDE.md/MEMORY.mdには載せない＝トークン節約。探索を触るとき search_ai.py から本ファイルを参照する。）

最終更新: 2026-06-14 / 対象AI_VER: `k4-megaeval-1mega-d2`（tree d2, tree_k=4, det≈16, maximin）

---

## 共通の根本原因（仮説）
いずれも **価値ネットの葉評価（材料・タイプ相性）は概ね正しい**が、以下の探索側の弱さで「読み筋」として悪手が選ばれる：

1. **相手モデル（maximin・top-k）が低確率の相手交代を過大評価**する。とくに「相手が引く → こちらの技で交代先を縛る/釣る」分岐の価値を高く見積もる。
2. **d2の地平線が浅く、相手の"最も自然な一手（主力STAB等）"で咎められる損を十分に減点できない**。
3. det（決定化）ノイズで僅差の手が時々逆転する。

→ 期待：**d3化／相手モデルで本命応手を厚くする／価値ネット再学習** のいずれかで、下記が「人間的に自然な手」に収束するはず。

## 再判定のやり方（共通）
各ケースの party спеック（下記）で局面を組み、`train_az2._net_ai(..., tree=True, tree_depth=2, tree_k=4, tree_det=16)` を作って
`ai.score_actions_tree(s1,s2,field)` の均衡値、および `ai(s1,s2,field)` の実選択を確認する。
深化後は **tree_depth=3** 等に上げて同じ局面で再評価し、「期待する手」が選ばれるかを見る。
（具体的な再現スクリプトの雛形はこのファイル末尾。）

## ケース1：過剰/甘い交代（ガブリアス → ルカリオ）
- **対戦**: M-1#1 サックー（自分） vs M-1#6 キョウタ（相手）
- **状況**: ガブリアス（自分・場）が、相手ドリュウズに対して **ルカリオへ交代**。ルカリオは交代先で **じしん（地面×2＝ルカリオのはがね/かくとうに抜群）を受けて落ちる**。
- **違和感**: ガブが既に場にいてドリュウズを処理できる状況で、ルカリオを差し出して落とすのは損に見える。
- **調査結果（事実）**:
  - 価値ネットの葉評価は正しい（残留してドリュウズ撃破＝高評価、ルカリオ交代死＝低評価）。
  - ただし **ルカリオはドリュウズに本来強い**（アイアンヘッドを0.25倍で半減、いわ等倍、インファイトはドリュウズに2倍）。**唯一じしん（ドリュウズの主力STAB）だけがルカリオに2倍**で刺さる。
  - d2のmaximinでは「相手の応手」が手ごとにズレて評価され、交代の最悪応手値が残留と拮抗～優位に出る。結果、交代が選ばれ得る。
- **保留理由**: ドミナンス除去（②）では消えない（探索の自己評価では劣位でない）。**「じしんという本命かつ唯一の刺し手に賭けない」読みの甘さ**＝相手モデル/深さの問題。
- **期待挙動（解消基準）**: ガブは**残留してじしん等で動く**（or じしんが来ない確証がある時のみ交代）。少なくとも「主力STABで一方的に咎められる交代」を既定で選ばない。
- **再現スペック**:
  - 自分(P1) ガブリアス@オボンのみ:いじっぱり:ドラゴンテール|じしん|ステルスロック|まきびし / フラエッテ(永遠)@フラエッテナイト / ルカリオ@ルカリオナイト:ようき:インファイト|コメットパンチ|ストーンエッジ|しんそく
  - 相手(P2) ドリュウズ（やわらかいすな・いじっぱり・じしん/アイアンヘッド/いわなだれ/つるぎのまい） / ルカリオ@ルカリオナイト / ゲッコウガ@こだわりスカーフ:へんげんじざい:なみのり/れいとうビーム/ヘドロウェーブ/あくのはどう
  - 局面：ガブ HP≈112/215・C-1、相手ドリュウズが場。

## ケース2：無効技を撃つ（ガブリアスがフェアリーにドラゴンテール）
- **対戦**: M-1#1 サックー（自分） vs M-1#2 攻め意識（相手）・3戦目・ターン3付近
- **状況**: ガブリアス（自分）が **エルフーン（くさ/フェアリー）にドラゴンテール（ドラゴン技）**。ドラゴンはフェアリーに **無効（0倍）**で、何も起きない。
- **違和感**: 0ダメの無効技を、しかも「おいかぜを展開して有利な（交代しそうにない）エルフーン」相手に撃つのは不自然。
- **調査結果（事実）**:
  - AIの被ダメ見積もりは正しい（ドラゴンテール→エルフーン=0.0、じしん=59を認識）。**ダメージ/無効のバグではない**。
  - 局面再構成では均衡値が **ドラゴンテール≈0.50 / じしん≈0.53 / ステロ≈0.58** と僅差。0ダメなのに高いのは、maximinが **「エルフーンが交代する分岐」でドラゴンテールが交代先を縛る価値**を計上しているため。det揺れで時々じしんを逆転する。
  - ※ドラゴンテールは無効相手には phaze（強制交代）も発生しない＝対面のエルフーンには完全に無価値。価値は「相手が引く」前提でのみ。
- **保留理由**: 相手モデルが低確率の交代を過大評価＋d2では「無駄ターン」を十分減点できない。ケース1と同根。
- **期待挙動（解消基準）**: 対面が無効相手のとき、**交代読みの phaze/ピボット技を主軸に選ばない**。じしん/ステルスロック等の有効手を選ぶ。
- **再現スペック**:
  - 自分(P1) ガブリアス@オボンのみ:いじっぱり:ドラゴンテール|じしん|ステルスロック|まきびし
  - 相手(P2) エルフーン@きあいのタスキ:おくびょう:ムーンフォース|おいかぜ|やどりぎのタネ|うそなき（いたずらごころ）
  - 局面：ガブ・エルフーンが対面、エルフーンはおいかぜ展開後。

## エンジンの既知改善点（AI挙動ではなくエンジン実装側。将来直すときの覚書）

  - **修正内容**：`battle.py` `_execute_move` の追撃ブロックを **本体の `_apply_secondary`/`_apply_recoil` の後ろ（`return logs` 直前）へ移動**。これで「本体ヒット→本体サマリ行→本体副次→追撃→追撃副次」の正しい順で処理・記録される。本体サマリ行は本体ダメのみ（追撃は別行 `おやこあい 追撃！ N`）。`total_dmg += pb_dmg` は撤去（追撃は末尾処理で `_apply_recoil(pb_dmg)` を個別適用）。
  - **影響**：HP最終結果は不変。副次効果の発動順・反動の丸め・ドレイン/かいがらのすずが本体基準（ガルーラ現実型では無関係）。921テスト全PASS。
  - **データ反映**：n=1（公開済み）は旧エンジン。フェーズ2(n=2)以降の新規計算は修正後（ユーザー指示=単純増分なので、ガルーラ戦は1戦目旧・2戦目新の混在＝影響小）。
